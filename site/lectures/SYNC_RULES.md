# Автосинхронизация публичного каталога лекций

Этот файл — точное правило для запланированной задачи Codex, которая обновляет `data.json`.

## Источники

1. Сначала проверить подключение Plaud через `plaud_get_current_user`.
2. Расписание брать только из опубликованного ICS: `https://monsterenergyaddict.github.io/msu111/111.ics`. Все времена нормализовать к `Europe/Moscow`.
3. Прочитать текущий `site/lectures/data.json` из `monsterenergyaddict/msu111`.
4. Получить записи Plaud с начала учебного года до текущего дня. Значение `duration` Plaud задано в миллисекундах; в каталоге хранить секунды.

## Отбор и сопоставление

- В каталог попадает каждая запись, которая пересекается с прошедшей парой из ICS не менее чем на пять минут. Ручная пометка имеет приоритет и допускается независимо от длительности.
- Ручная пометка имеет формат `Лекция: [Название предмета] Тема`. Она создаёт запись с `source: "manual"`, даже если занятие не найдено в ICS.
- Обычную запись сопоставить с одним прошедшим событием ICS, с которым у неё максимальное пересечение времени.
- Для карточки, связанной с ICS, записать `lessonNumber`: это порядковый номер события за этот день после сортировки по началу, начиная с 1.
- Из `DESCRIPTION` события извлечь `instructor`, только если после строки с аудиторией остаётся уверенно распознанное ФИО преподавателя; иначе поле оставить пустым. Не придумывать преподавателя по содержанию Plaud.
- Для каждого `scheduleUid` оставить одну запись: сначала ручная пометка, затем запись с наибольшим пересечением, затем ту, что начинается ближе к началу пары, затем более длинную.
- Уже опубликенные карточки не удалять автоматически. При изменении названия или готовности заметки обновлять существующую карточку с тем же `plaudFileId`.

## Содержание и публичная ссылка

- Для каждого нового кандидата и каждой карточки со статусом `processing` запросить AI-заметку Plaud.
- Если заметка доступна, создать краткое содержание из 2–4 предложений и максимум четыре тезиса, строго по заметке; статус `ready`. Если заметки нет или она пуста, хранить пустые `summary` и `topics`, статус `processing`.
- Для **каждой** готовой карточки без `shareUrl` сначала открыть Share в Plaud Web. Если видны «Copy link» и «Remove link», ссылка уже существует: нажать «Copy link», проверить формат `https://web.plaud.ai/s/...` и сохранить её в `shareUrl` — не создавать дубликат.
- Только если в Share нет готовой ссылки и доступна «Create link», создать «Anyone with the link»: включить **Audio**, **Transcript**, **Highlights** и **Summary**, оставить срок действия `Never expires`, затем скопировать точный URL вида `https://web.plaud.ai/s/...` в `shareUrl`.
- В публичный JSON нельзя помещать исходную закрытую ссылку `/file/<id>`, временные `presigned_url`/`data_link`, данные аккаунта или иные персональные поля. Поле `plaudFileId` остаётся только техническим идентификатором синхронизации.

## Запись в GitHub

- Валидировать, что каждая карточка содержит `plaudFileId`, `startedAt`, `course` и `status`; у карточки из ICS также должен быть `lessonNumber`. Поле `instructor` и `shareUrl` необязательны.
- Обновлять `updatedAt` и коммитить `data.json` только при содержательном изменении.
- При отсутствии изменений не создавать коммит и не отправлять сообщение.
- При ошибке Plaud/GitHub или неоднозначном совпадении не портить существующий JSON; сообщить только о проблеме.
