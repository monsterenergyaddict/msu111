# Автоматическое обновление лекций без VPS

Подготовлено для `monsterenergyaddict/msu111`. Сайт и прежний каталог остаются
в `site/lectures/`; код этого каталога размещается в `tools/lecture-sync/`,
а `workflow.yml` — в `.github/workflows/plaud-sync.yml`.

## Что делает новая схема

GitHub Actions получает метаданные и AI-заметки через официальный Plaud CLI,
сопоставляет записи с `site/111.ics` в московском времени, а публичные ссылки
читает и создаёт в Plaud Web через браузер. Пароль Plaud в коде не нужен.
При существующей ссылке используется она же. Публичный JSON содержит только
карточки занятий и публичные ссылки; исходные аудио и полный личный архив
в репозиторий не попадают. Обычные записи требуют пяти минут пересечения
с прошедшей парой; короткие лекции не отбрасываются. Спорные совпадения
пропускаются. Ручные исправления и отменённые пары сохраняются.

Код не переносит старую постоянно работающую админку и почтовых ботов.

## Готовность

Перенос требует повторного входа в Plaud CLI и Plaud Web, сохранения
зашифрованного подключения в GitHub Secrets и проверки одной новой записи.
Без этих шагов обновление не запущено. По расписанию публикация выключена,
пока переменная репозитория `PLAUD_SYNC_ENABLED` не станет `true`.
Создание ссылок зависит от текущего интерфейса Plaud Web. Если интерфейс
или вход изменится, запуск завершится ошибкой без перезаписи каталога в GitHub.

## Первоначальное подключение

Требуются Node.js 22 и pnpm 11.25.0. В каталоге `tools/lecture-sync`:

```sh
pnpm install --frozen-lockfile --ignore-scripts
pnpm exec playwright install chromium
pnpm run login
```

Последняя команда запускает локальный помощник из `package.json`. Он предлагает
два обычных входа: официальный OAuth для CLI, затем Plaud Web.

После входа локальная `.private/` содержит:

- `bootstrap.enc` — подключение, зашифрованное AES-256-GCM;
- `session-key.txt` — ключ расшифровки;
- `web-state.json` — браузерная сессия, хранится только локально.

Официальный CLI также сохраняет собственную авторизацию в `~/.plaud/tokens.json`.
Не публикуйте эти файлы и не отправляйте их в чат.

В закрытые GitHub Actions Secrets этого репозитория добавить:

- `PLAUD_SESSION_KEY`: содержимое `session-key.txt`;
- `PLAUD_BOOTSTRAP`: содержимое `bootstrap.enc`, закодированное в Base64.

Это предоставляет исполнителям workflow доступ к подключённому аккаунту Plaud.
До переноса подключения нужно согласие владельца аккаунта. Ключ и исходные
данные входа никогда не должны попадать в коммит, открытый журнал или артефакт.

Обычный `GITHUB_TOKEN` выдаёт GitHub для одного запуска, личный токен не нужен.
Workflow получает право менять файлы, но изменяет только `site/lectures/data.json`.
Обновление из pull request не запускается.

## Проверка и включение

1. Разместить workflow и код в `main`.
2. Запустить **Update Plaud lectures** вручную, без публикации. Он читает
   записи и проверяет сопоставления, не создаёт ссылок и не меняет JSON.
3. Повторить с ID одной новой лекции в `pilot` и включённым `publish`.
4. Проверить карточку и воспроизведение в Plaud по публичной ссылке.
5. Установить переменную `PLAUD_SYNC_ENABLED=true`.

Затем проверка запускается каждые два часа с 10:17 до 20:17 по Москве,
с понедельника по субботу. GitHub может задерживать запланированные задания.
Mac для этих запусков не требуется. Старая задача Codex может оставаться
приостановленной, чтобы два процесса не публиковали одновременно.

Сессия и checkpoint ссылок сохраняются между запусками только в зашифрованном
артефакте `plaud-session-v1` со сроком хранения 30 дней. Обновлённые OAuth-токены
переносятся вместе с этим состоянием. Нет открытых скриншотов, browser traces
или файлов cookies в артефактах. При потере состояния/истечении авторизации
может понадобиться повторное подключение. Публичный сайт продолжает показывать
сохранённые лекции независимо от этой автоматики.

После коммита workflow отдельно публикует Pages: коммит от `GITHUB_TOKEN`
сам не запускает соседний workflow по событию push. Одновременная ручная
правка каталога приводит к отказу push, а не к принудительной перезаписи.

## Проверки

`pnpm test` проверяет сопоставления с расписанием, короткие лекции, позднюю
загрузку, две пары в одном файле, конкурирующие записи, сохранение ручных
правок, идемпотентность и подлинность зашифрованного состояния.
Полная проверка публикации требует действующих входов в Plaud и GitHub.
